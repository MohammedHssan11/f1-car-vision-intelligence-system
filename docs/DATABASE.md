# Database and State Storage Documentation

## Database Presence Status

No SQL database, NoSQL database, Redis cache, vector database, or external state service is implemented in the active codebase.

The system relies on:

1. In-memory state in Python dictionaries during a video run.
2. Local filesystem storage for uploads and generated results.
3. Standalone CSV/PNG outputs from `damage_video_inference.py`.

## In-Memory State Storage

State tracking is maintained in `tracking_memory/tracker_core.py`.

| Field | Value |
| ----- | ----- |
| Global variable | `cars` |
| Type | `dict` |
| Key | YOLO/ByteTrack `track_id` as `int` |
| Value | `CarState` instance |

Lifecycle:

1. `src/pipeline.py` clears `cars` at the start of `run_full_pipeline()`.
2. `update_cars()` creates a `CarState` for each new track ID.
3. Every detected frame updates position, bounding box, speed, acceleration, path length, and last seen frame.
4. Team classification is set once per car if it was previously unset.
5. Damage state is updated when crop-level damage detections overlap a car box by IoU greater than `0.3`.
6. No per-run automatic removal of old car objects occurs during a video; state lasts until the next run clears it.

## File-Based Runtime Storage

| Path | Purpose | Lifecycle |
| ---- | ------- | --------- |
| `uploads/images/` | Input storage for `/damage/image`. | Files persist until manually removed. |
| `uploads/videos/` | Input storage for `/pipeline/video` and one allowed local root for `/pipeline/run`. | Files persist until manually removed. |
| `tracker/` | Bundled sample videos and ByteTrack config; also an allowed local root for `/pipeline/run`. | Repository/demo assets persist until manually changed. |
| `app/static/results/` | Annotated image outputs. | Files persist until manually removed. |
| `outputs/videos/` | Annotated pipeline video outputs. | Files persist until manually removed. |

## Standalone Damage Timeline Artifacts

`damage_video_inference.py` is separate from the FastAPI request path. When run directly, it can generate:

| Artifact | Purpose |
| -------- | ------- |
| `damage_timeline.csv` | Frame-by-frame cumulative damage count. |
| `damage_timeline.png` | Matplotlib plot of damage count over frames. |
| `damage_timeline_output.mp4` | Annotated standalone video output, when generated by the script. |

CSV schema:

| Column | Type | Meaning |
| ------ | ---- | ------- |
| `Frame` | Integer | Sequential frame index. |
| `Damage_Count` | Integer | Cumulative unique damage regions tracked by the standalone script. |
